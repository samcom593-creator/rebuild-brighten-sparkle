# Galaxy navigation and workflow audit — 2026-11-25

## Scope and evidence

This is a source and focused-test audit of the repair branch based on main `d0302b334f7264ed214f8aaca5d174ef3fc3fc63`. It inventories every registered route in `src/App.tsx` and every entry in the primary, applicant and account navigation manifests. It also traces the lead worklists, shared navigation visibility, command palette, mobile navigation, recruiting/training section navigation and the affected read/mutation contracts.

The source census contains **304 route declarations: 82 explicit route redirects and 222 component entries, including the wildcard recovery route**. The `AgentDetail` component now performs an additional compatibility redirect to the canonical producer profile; it remains a component entry in this AST census. Of these, 247 inherit `AuthenticatedShell`, whose own `ProtectedRoute` requires a session. The sidebar manifests contain **47 entries and 43 unique hrefs** across role variants. Every sidebar href resolves to a registered path after removing its query string. The complete path inventory appears below; a path sharing a component is not automatically redundant, because contracting and settings use the path to select different work.

Evidence was read from `src/App.tsx`, `src/components/ProtectedRoute.tsx`, `src/components/layout/AuthenticatedShell.tsx`, `src/components/layout/agentCloudNavigation.ts`, `GlobalSidebar.tsx`, `MobileBottomNav.tsx`, `src/components/command/CommandPalette.tsx`, page source modules, and the relevant database migration. **Authenticated live rendering, actual user roles/grants, live database row counts, conversion outcomes and route usage were not verified by this audit.** No route is declared unused merely because a static reference was not found. No historical KJ data or access/routing rules were changed.

## Operational relevance levels

**These levels are analyst classifications from source-defined purpose, intended audience and existing disposition.** They describe the work a destination supports and its intended navigation prominence. No engagement telemetry, measured visit frequency, adoption, conversion effectiveness or additional live checks were used to assign them. “Daily” identifies a primary operating flow for its intended audience; it is not a measured claim about how often a particular user visits.

| Level | Basis for the classification | Navigation and review implication |
| --- | --- | --- |
| L1 — Core daily work | A primary execution path: assigned tasks, calling, recruiting, client follow-up, production/finance work, or the main applicant conversion, onboarding and learning journey. | Prioritize clear access and reliable completion for the intended audience. Public funnel and applicant steps can be L1 without belonging in the dashboard sidebar. |
| L2 — Role-specific operations | A specialist operational task: management review, staff/account administration, imports, contracting, carrier reconciliation, business recovery, publishing, or system control. | Keep access within the relevant role or contextual workflow. The existing access column remains the authority for the frontend gate; this rating grants no permission. |
| L3 — Supporting or occasional | Reference, help, preferences, optional tools, recognition, personal productivity, or historical/secondary review that supports the main work. | Keep it reachable through the appropriate secondary or contextual entry. Legal, security and support pages can be essential when needed; this level does not justify deletion. |
| L4 — Compatibility or recovery | An explicit redirect, identified parallel/legacy entry, access-recovery or transitional endpoint, short-link routing, or unknown-route recovery. | Preserve existing links and recovery journeys. Prefer the canonical work destination for new primary navigation. L4 is a navigation classification, not evidence that the endpoint is unused or unimportant. |

The task determines the level, rather than the permission gate alone: Lead Manager is L1 because assignment is its primary execution path, while carrier reconciliation and staff-account administration are L2 specialist operations. Business recovery queues remain L2; L4 recovery means routing or account-access recovery. A functional older workspace can remain L2 or L3 while consolidation is pending. The contracting-review menu link is L2 for its selected team-review mode, while the main team worklist is L1.
